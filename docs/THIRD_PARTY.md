# Third-party inventory

## Rust crates linked into the runtime

| Crate | Licence | Used for | Notes |
|---|---|---|---|
| pelite 0.10 | MIT | PE parsing (`pe` crate) | Five hazards found by hostile-input testing, all guarded in our code (`crates/pe/src`): (1) `int()` rejects the 4-byte-aligned import lookup tables GNU ld emits: thunk arrays are walked by hand (`analyze.rs`). (2) Alignment is checked against the RVA, not the file offset: `analyze.rs::check_layout` rejects mismatched sections, and unaligned input is copied. (3) `VersionInfo` slices unchecked and panics on a crafted resource: replaced by our own parser (`version.rs`). (4) `resources()` dereferences a misaligned directory (SIGABRT in debug builds): `res_rva % 4` guard in `analyze.rs`. (5) The base-relocation block iterator never terminates on `SizeOfBlock` 0xFFFFFFFD..FF: own block walk in `analyze.rs`. Also: no delay-import support (handled by hand), unbounded `derva_c_str` (all strings go through `read_bounded`), and `ordinal_base()` truncates Base to u16 (we read the u32 field). |
| memchr 2 | Unlicense OR MIT | Installer marker search (`runtime-pe`, `installer.rs`); also the bounded NUL-terminated string reader (`read_bounded`) in `analyze.rs` | |
| serde 1 | MIT OR Apache-2.0 | Serialisation (`runtime-pe` report types, `runtime-core` `metadata.json` and `AppId`) | Feature `derive`. |
| serde_json 1 | MIT OR Apache-2.0 | JSON (`runtime-core` metadata, `runtime-cli` `--json` output); dev-dependency of `runtime-pe` | |
| thiserror 2 | MIT OR Apache-2.0 | Error types (`runtime-pe`, `runtime-core`, `runtime-backend-wine`) | |
| clap 4 | MIT OR Apache-2.0 | CLI argument parsing (`runtime-cli`) | Feature `derive`. |
| tracing 0.1 | MIT | Log events in `runtime-core`, `runtime-backend-wine` and `runtime-cli` (for example a failed cleanup after a panic during install) | |
| tracing-subscriber 0.3 | MIT | Prints those events to stderr, filtered by `RUNTIME_LOG` (`runtime-cli`) | Feature `env-filter`. |
| zip 8 | MIT | Zip extraction for `runtime install` (`runtime-core`); dev-dependency of `runtime-cli` for building test archives | Direct dependency with `default-features = false, features = ["deflate-flate2"]`: only stored + deflate (no bzip2, zstd, lzma, AES, zopfli, `time`). Transitive: crc32fast, flate2, indexmap (equivalent, hashbrown), memchr, typed-path. Hazards handled in `crates/core/src/unzip.rs` (the crate is never handed an archive we have not validated): its central-directory parse sizes a `Vec` from whichever end record it settles on (count taken from the "entries on this disk" field, zip64 when the count, size OR offset is saturated) and it walks back over EVERY `PK\5\6` in the file, skipping candidates that fail its own checks, so `prevalidate` strictly checks the single end record, the zip64 record, the counts (at most 20 000), the directory size (at most 64 MiB) and walks the whole central directory before `ZipArchive::new`, and the crate reads through a reader that zeroes everything before the directory so no other end record can be found; it keeps only the LAST of two entries with the same raw name (the stated count is compared with the number of names it kept); `enclosed_name` is not relied on (names are parsed with `WinPath`); its extract helpers are not used: extraction is our own `create_new` streaming loop that never applies the archive's permission bits or creates links. Not supported: archives with data before the first entry (self-extracting). Its own `deflate` feature selects zlib-rs (licence `Zlib`, not in `deny.toml`), so the backend is chosen via `flate2` below. |
| flate2 1 | MIT OR Apache-2.0 | Deflate backend for `zip` (`runtime-core`); `Crc`/`DeflateEncoder` in tests | Direct dependency with `default-features = false, features = ["rust_backend"]` solely to select the pure-Rust `miniz_oxide` backend (MIT OR Zlib OR Apache-2.0; pulls adler2 0BSD OR MIT OR Apache-2.0 and simd-adler32 MIT). |
| libc 0.2 | MIT OR Apache-2.0 | `O_NONBLOCK` for opening untrusted files (`metadata.json`, install input) so a FIFO swapped in after the lstat cannot block, `mkfifo` in tests (`runtime-core`); ignoring SIGINT while a program runs (`runtime-cli`, `run.rs`) | Already in the lock file through pelite. |
| tempfile 3 | MIT OR Apache-2.0 | Temporary directories in tests | Dev-dependency only (`runtime-core`, `runtime-backend-wine`, `runtime-cli`); never linked into release binaries. |
| png 0.18 | MIT OR Apache-2.0 | PNG encoding of decoded ICO/DIB icon data (`runtime-desktop::icon`) | Phase 3 Task 3 spike: evaluated hand-rolling PNG encoding versus a vetted crate; `png` is small, widely used, and the project's own stance (`docs/THIRD_PARTY.md`'s rule of thumb, see the `zip`/`flate2` rows) is to prefer a vetted format crate over hand-rolled encoding. Only `Encoder`/`Writer` (RGBA8 output) are used; PNG *decoding* is never needed (an already-PNG ICO entry is passed through unchanged, byte-for-byte, never round-tripped through this crate). Transitive: bitflags, crc32fast, fdeflate, flate2 (a second copy of the workspace's own dependency; Cargo unifies to one resolved version, 1.1.10, with the union of requested features — still only `rust_backend`+`runtime_detection` are ever *activated*: `flate2` 1.1.10 makes every backend, including `zlib-rs`, an optional `dep:` feature (unlike the older version this workspace previously locked to), so `zlib-rs` v0.6.8 appears as a resolvable *candidate* in `Cargo.lock` — confirmed via `cargo tree -i zlib-rs` (empty) and `cargo build --workspace --all-targets` producing no `Compiling zlib-rs` line — but is never compiled or linked; `cargo deny check` passes clean, `licenses ok`), miniz_oxide (a second version, 0.9.1, alongside the workspace's existing 0.8.9 via `zip`; `cargo deny`'s `multiple-versions` is `warn`, not an error, and both are MIT OR Apache-2.0 either way), adler2, simd-adler32. |

This table lists direct dependencies only (every `[dependencies]` and `[dev-dependencies]` entry of every crate under `crates/`; the licences are the `license` fields of `cargo metadata` for the versions in `Cargo.lock`; the workspace crates `runtime-*` are this project's own). Update it whenever a `Cargo.toml` changes. `cargo deny` (see `deny.toml`) governs the whole transitive set and its licence allow-list. For example `unicode-ident` (pulled in by the proc-macro crates) is `(MIT OR Apache-2.0) AND Unicode-3.0`, which is why `Unicode-3.0` is in `deny.toml`.
